# AI-usage log

Καταγραφή των σημαντικών χρήσεων εργαλείων AI στο έργο (Ενότητα 4.4 της εκφώνησης). Δεν καταγράφουμε κάθε προτροπή. Καταγράφουμε τις περιπτώσεις που επηρέασαν τον κώδικα, τους ελέγχους, τον σχεδιασμό ή την τεκμηρίωση.

## Κανόνες

- Το log ενημερώνεται **σε κάθε sprint**, όχι μόνο στο τέλος.
- Σε κάθε sprint καταγράφεται **τουλάχιστον μία** περίπτωση όπου η πρόταση του εργαλείου ήταν λανθασμένη, ελλιπής ή επικίνδυνη, μαζί με τον τρόπο που εντοπίστηκε.
- Η έγκριση για merge δίνεται πάντα από μέλος της ομάδας. Ένα εργαλείο AI μπορεί να είναι μόνο πρόσθετος reviewer.
- Κωδικοί, κλειδιά API και προσωπικά δεδομένα δεν μπαίνουν ποτέ σε προτροπές.
- Η ευθύνη για την ορθότητα και την ασφάλεια ανήκει στην ομάδα, όποιος κι αν έγραψε τον κώδικα.

### Λανθασμένες ή ελλιπείς προτάσεις στο Sprint 0

#### AI-00-10: Λανθασμένα ερωτήματα SPARQL στη διερεύνηση του Wikidata

| Πεδίο | Περιεχόμενο |
|-------|-------------|
| Ημερομηνία | 2026-11-19 |
| Μέλος | georgeEuaggel |
| Εργαλείο | Claude Code (Claude Opus 5.5) |
| Σκοπός | Ερωτήματα SPARQL για τις σχέσεις της Mary Shelley (Q47152) και για το *Frankenstein* (Q150827) |
| Τι πρότεινε | (α) Ερώτημα για τον πατέρα, που έδενε τη μεταβλητή `?p` και με `VALUES` και με `BIND`. Επέστρεψε κενό αποτέλεσμα με HTTP 200, χωρίς κανένα σφάλμα. (β) Ερώτημα για το *Frankenstein* χωρίς `DISTINCT`. Επέστρεψε την ίδια γραμμή 41 φορές, επειδή το αντικείμενο έχει πολλές τιμές τίτλου (P1476). |
| Απόφαση | Απορρίφθηκε. Τα ερωτήματα ξαναγράφτηκαν με `wikibase:directClaim` και `DISTINCT`, και έδωσαν το σωστό αποτέλεσμα: πατέρας William Godwin (Q188569), μητέρα Mary Wollstonecraft (Q101638), σύζυγος Percy Bysshe Shelley (Q93343). |
| Επαλήθευση | Εντοπίστηκε με έλεγχο των αποτελεσμάτων. Το (α) έδωσε κενό αποτέλεσμα για δεδομένο που ξέραμε ότι υπάρχει, και το (β) είχε προφανή διπλότυπα. |
| Μάθημα | Ένα ερώτημα που τρέχει χωρίς σφάλμα δεν είναι απαραίτητα σωστό. Τα ερωτήματα SPARQL των adapters θα έχουν πάντα `DISTINCT` και `LIMIT`, και έλεγχο με fixture γνωστού αποτελέσματος. Ένα κενό αποτέλεσμα με HTTP 200 πρέπει να αντιμετωπίζεται ως πιθανό σφάλμα, όχι ως «δεν βρέθηκε». |
