# Μορφή αρχείου αποστολής

Κάθε αποστολή είναι ένα αρχείο YAML στο `src/main/resources/missions/` ([ADR-0001](adr/0001-mission-description-model.md), TS-06). Μια νέα αποστολή με τους υπάρχοντες τύπους γρίφων χρειάζεται μόνο νέο αρχείο, χωρίς αλλαγή στον κώδικα (MVP-9).

Τα αρχεία διαβάζονται και ελέγχονται **στην εκκίνηση**. Ένα άκυρο αρχείο σταματά την εφαρμογή με μήνυμα που δείχνει το αρχείο και το πεδίο, π.χ.:

```text
Άκυρο αρχείο αποστολής file [.../missions/villa-diodati.yml]:
  - puzzles[1].unlockedBy[0]: άγνωστο στοιχείο 'leter-1816'
```

Οι δείκτες ξεκινούν από το 0: `puzzles[1]` είναι ο δεύτερος γρίφος του αρχείου. Ο ίδιος έλεγχος τρέχει στο `./mvnw verify` για όλα τα αρχεία (`MissionFilesTests`), άρα ένα άκυρο αρχείο δεν περνά το CI.

Πλήρες παράδειγμα: [`villa-diodati.yml`](../src/main/resources/missions/villa-diodati.yml).

## Αποστολή

| Πεδίο | Υποχρεωτικό | Περιγραφή |
|-------|-------------|-----------|
| `id` | ναι | Μοναδικό και σταθερό, π.χ. `villa-diodati`. Όλα τα id του αρχείου έχουν πεζά λατινικά, ψηφία και παύλες. |
| `version` | ναι | Ακέραιος ≥ 1. Αυξάνεται σε κάθε αλλαγή του περιεχομένου, ώστε ένα playthrough να ξέρει με ποια έκδοση ξεκίνησε. |
| `title`, `summary` | ναι | Τίτλος και σύντομη περιγραφή για τον κατάλογο |
| `minPlayers`, `estimatedMinutes` | ναι | Ακέραιοι ≥ 1 |
| `paths` | ναι | Οι διαδρομές: `id`, `title` |
| `evidence` | ναι | Τα στοιχεία του ημερολογίου (παρακάτω) |
| `puzzles` | ναι | Οι γρίφοι (παρακάτω) |

## Στοιχεία (`evidence`)

| Πεδίο | Υποχρεωτικό | Περιγραφή |
|-------|-------------|-----------|
| `id` | ναι | Το id που χρησιμοποιούν τα `unlockedBy` και `reveals` των γρίφων |
| `path` | ναι | Η διαδρομή όπου βρίσκεται |
| `title` | ναι | Ό,τι βλέπουν οι παίκτες στο ημερολόγιο |
| `initial` | όχι | `true` αν είναι διαθέσιμο από την αρχή (π.χ. το αντικείμενο που ξεκινά μια διαδρομή). Αλλιώς το αποκαλύπτει ακριβώς ένας γρίφος με το `reveals`. |

## Γρίφοι (`puzzles`)

Κοινά πεδία για όλους τους τύπους:

| Πεδίο | Υποχρεωτικό | Περιγραφή |
|-------|-------------|-----------|
| `id` | ναι | Μοναδικό στην αποστολή |
| `type` | ναι | `TEXT_ANSWER`, `SEQUENCE`, `COOPERATIVE` ή `COMBINATION` |
| `title` | ναι | Ο τίτλος του γρίφου |
| `prompt` | όχι | Η εκφώνηση. Δεν πρέπει να περιέχει την απάντηση. |
| `path` | όχι | Η διαδρομή. Συνήθως λείπει μόνο από τον τελικό γρίφο. |
| `unlockedBy` | όχι | Τα στοιχεία που πρέπει να υπάρχουν **όλα** στο ημερολόγιο για να ανοίξει ο γρίφος. Χωρίς αυτό, ο γρίφος είναι ανοιχτός από την αρχή. |
| `reveals` | όχι | Τα στοιχεία που προστίθενται στο ημερολόγιο όταν λυθεί |
| `source` | όχι | Εξωτερική πηγή: `provider` (`wikidata` ή `openlibrary`) και `snapshot`, η διαδρομή του αποθηκευμένου αντιγράφου σχετικά με το `snapshots/` ([ADR-0002](adr/0002-external-data-snapshots.md)). Η ύπαρξη του αρχείου δεν ελέγχεται ακόμη, γιατί τα snapshots έρχονται με το TS-09. |
| `answer` | ναι | Η σωστή απάντηση, ανάλογα με τον τύπο |
| `completesMission` | όχι | `true` μόνο για τον τελικό γρίφο. Υπάρχει ακριβώς ένας. |

Πεδία ανά τύπο. Ένα πεδίο που δεν ανήκει στον τύπο του γρίφου είναι λάθος, ώστε ένα λάθος να μη χάνεται σιωπηλά.

| Τύπος | Δημόσια πεδία | `answer` |
|-------|---------------|----------|
| `TEXT_ANSWER` | – | `accepted`: οι αποδεκτές απαντήσεις (τουλάχιστον μία) |
| `SEQUENCE` | `actions`: οι ενέργειες (`id`, `title`), τουλάχιστον 2. Δεν τις γράφουμε με τη σωστή σειρά. | `steps`: τα id των ενεργειών με τη σωστή σειρά (τουλάχιστον 2) |
| `COOPERATIVE` | `contributors`: πόσοι διαφορετικοί παίκτες πρέπει να απαντήσουν (≥ 2 και ≤ `minPlayers`) | `accepted` |
| `COMBINATION` | `fields`: τα πεδία που συμπληρώνει ο παίκτης (`id`, `title`) | `evidence`: τα στοιχεία που πρέπει να επιλεγούν από το ημερολόγιο, ή/και `values`: οι αποδεκτές τιμές κάθε πεδίου (`id πεδίου: [τιμές]`) |

```yaml
  - id: archive-1816
    type: COMBINATION
    title: "Το αρχείο του 1816"
    unlockedBy: [meeting-place, sitter, book-identity]
    fields:
      - { id: place, title: "Τόπος" }
      - { id: year, title: "Έτος" }
    answer:
      values:
        place: ["Cologny", "Κολονί"]
        year: ["1818"]
    completesMission: true
```

Η σύγκριση των απαντήσεων (κεφαλαία, τόνοι, κενά) ανήκει στον μηχανισμό του παιχνιδιού και όχι στο αρχείο.

## Οι σωστές απαντήσεις δεν φεύγουν από το backend

Το `answer` διαβάζεται από το αρχείο, αλλά δεν γράφεται ποτέ σε JSON (`@JsonProperty(access = WRITE_ONLY)` στο `Puzzle`). Το `toString()` δείχνει `Answer[κρυφή]`. Ο έλεγχος `MissionAnswersAreHiddenTests` το επιβεβαιώνει για κάθε αρχείο. Ένα template ή ένα DTO δεν πρέπει να διαβάζει ποτέ το `answer()`.

## Τι ελέγχεται στην εκκίνηση

1. **YAML:** άγνωστο πεδίο (π.χ. `unlockBy`), διπλό κλειδί, άγνωστος τύπος γρίφου, λάθος τύπος τιμής. Το μήνυμα δείχνει και τη γραμμή.
2. **Δομή (Bean Validation):** υποχρεωτικά πεδία, μορφή των id, θετικοί αριθμοί.
3. **Αναφορές:** διπλά id, αναφορές μόνο σε διαδρομές, στοιχεία και ενέργειες που υπάρχουν, τα πεδία κάθε τύπου γρίφου, ακριβώς ένας τελικός γρίφος. Κάθε στοιχείο το αποκαλύπτει το πολύ ένας γρίφος, και ένα `initial` στοιχείο κανένας.
4. **Ξεκλείδωμα**, μόνο αν τα προηγούμενα είναι σωστά:
   - κανένας κύκλος, π.χ. ο Α περιμένει στοιχείο του Β και ο Β στοιχείο του Α,
   - κάθε στοιχείο είναι `initial` ή το αποκαλύπτει κάποιος γρίφος,
   - αν η αποστολή «παιχτεί» από τα αρχικά στοιχεία, ανοίγουν όλοι οι γρίφοι, μαζί με τον τελικό.
5. **Ανάμεσα σε αρχεία:** δύο αρχεία δεν έχουν το ίδιο `id`.

## Χρήση από τα άλλα modules

Το public API είναι το `MissionCatalog` (`com.escapehub.mission.application`):

| Μέθοδος | Επιστρέφει |
|---------|------------|
| `all()` | Όλες οι αποστολές, με τη σειρά των ονομάτων των αρχείων |
| `find(id)` | `Optional<Mission>` |
| `get(id)` | Την αποστολή, ή `NotFoundException` (404) |

Το `Mission` είναι καθαρή Java (records του `mission.domain`) και έχει επίσης τα `initialEvidence()`, `findEvidence(id)` και `findPuzzle(id)`.
