# ADR-0001: Μοντέλο περιγραφής αποστολών

- **Κατάσταση:** Προτεινόμενη
- **Ημερομηνία:** 2026-11-19
- **Σχετικά:** TS-06, US-19

## Πλαίσιο

Το MVP-9 ζητά να μπορεί να προστεθεί μια δεύτερη, μικρή αποστολή που χρησιμοποιεί ήδη υποστηριζόμενους τύπους γρίφων, **χωρίς αλλαγές στον κώδικα του μηχανισμού**. Η εκφώνηση ξεκαθαρίζει ότι **δεν** ζητείται γενική μηχανή κανόνων ή γλώσσα περιγραφής αποστολών.

Χρειαζόμαστε λοιπόν έναν τρόπο να περιγράφουμε σε δεδομένα:

- διαδρομές, στοιχεία και γρίφους,
- ποιος γρίφος ξεκλειδώνει πότε και τι αποκαλύπτει,
- τις σωστές απαντήσεις,

ενώ η συμπεριφορά κάθε **τύπου** γρίφου μένει στον κώδικα.

## Απόφαση

1. Κάθε αποστολή είναι ένα αρχείο **YAML** στο `src/main/resources/missions/`, με `id` και ακέραιο `version`.
2. Οι **τύποι γρίφων** είναι κλειστό σύνολο στον κώδικα. Ο καθένας υλοποιεί ένα κοινό interface (strategy pattern):

   | Τύπος | Συμπεριφορά |
   |-------|-------------|
   | `TEXT_ANSWER` | Ελεύθερη απάντηση, συγκρίνεται με λίστα αποδεκτών τιμών μετά από κανονικοποίηση |
   | `SEQUENCE` | Ενέργειες με συγκεκριμένη σειρά. Λάθος βήμα μηδενίζει την ακολουθία. |
   | `COOPERATIVE` | Απαιτεί συνεισφορές από N διαφορετικούς χρήστες |
   | `COMBINATION` | Επιλογή συγκεκριμένων στοιχείων από το ημερολόγιο ή συμπλήρωση πεδίων |

3. Οι **κανόνες ξεκλειδώματος** είναι δηλωτικοί και απλοί. Το `unlockedBy` είναι λίστα στοιχείων που πρέπει να υπάρχουν όλα (λογικό ΚΑΙ). Κενή λίστα σημαίνει διαθέσιμο από την αρχή. Δεν υπάρχουν εκφράσεις, script ή γλώσσα κανόνων.
4. Οι **σωστές απαντήσεις** βρίσκονται στο αρχείο της αποστολής, στο backend, και δεν εκτίθενται ποτέ στο API. Οι γρίφοι με εξωτερικά δεδομένα δηλώνουν την πηγή και το snapshot τους, αλλά η επικύρωση γίνεται πάντα με την αποθηκευμένη τιμή ([ADR-0002](0002-external-data-snapshots.md)).
5. Τα αρχεία **επικυρώνονται στην εκκίνηση**:
   - Bean Validation πάνω σε Java records,
   - έλεγχος ότι κάθε αναφορά σε στοιχείο ή γρίφο υπάρχει,
   - έλεγχος ότι δεν υπάρχουν κύκλοι,
   - έλεγχος ότι η αποστολή είναι ολοκληρώσιμη.

   Ένα άκυρο αρχείο σταματά την εκκίνηση με σαφές μήνυμα. Ο ίδιος έλεγχος τρέχει και ως test για όλα τα αρχεία.

### Παράδειγμα (απόσπασμα)

```yaml
id: villa-diodati
version: 1
title: "Το μυστήριο της Villa Diodati"
summary: "Ένα κλειδωμένο αρχείο του 1816 και τρία αντικείμενα."
minPlayers: 2
estimatedMinutes: 45

paths:
  - id: letter
    title: "Η επιστολή"
  - id: portrait
    title: "Το πορτρέτο"
  - id: book
    title: "Το βιβλίο"

evidence:
  - id: letter-1816
    path: letter
    title: "Επιστολή, Ιούνιος 1816"
  - id: meeting-place
    path: letter
    title: "Τόπος συνάντησης: Villa Diodati, Cologny"
  - id: sitter
    path: portrait
    title: "Πρόσωπο του πορτρέτου: Mary Shelley"
  - id: book-identity
    path: book
    title: "Βιβλίο: Frankenstein (1818)"

puzzles:
  - id: restore-letter
    path: letter
    type: SEQUENCE
    unlockedBy: []
    steps: [uv-lamp, seal, postscript]
    reveals: [letter-1816]

  - id: meeting-location
    path: letter
    type: TEXT_ANSWER
    unlockedBy: [letter-1816]
    source: { provider: wikidata, snapshot: wikidata/search-villa-diodati.json }
    answer:
      accepted: ["Cologny"]
    reveals: [meeting-place]

  # ... portrait-family (COOPERATIVE), modern-prometheus (TEXT_ANSWER)

  - id: archive-1816
    type: COMBINATION
    unlockedBy: [meeting-place, sitter, book-identity]
    answer:
      place: meeting-place
      person: sitter
      year: "1818"
    completesMission: true
```

Το ακριβές σχήμα θα οριστικοποιηθεί στο TS-06.

## Συνέπειες

**Θετικές**

- Μια νέα αποστολή με υπάρχοντες τύπους γρίφων χρειάζεται μόνο νέο αρχείο YAML και snapshots, ελέγξιμα στο diff του PR (MVP-9).
- Ο μηχανισμός ελέγχεται ανεξάρτητα από το περιεχόμενο, με μικρές αποστολές-fixtures στα tests.
- Τα αρχεία είναι αναγνώσιμα και περνούν από review όπως ο κώδικας.

**Αρνητικές**

- Ένας νέος **τύπος** γρίφου απαιτεί κώδικα. Αυτό είναι αποδεκτό και αναμενόμενο.
- Η εκφραστικότητα είναι περιορισμένη. Μόνο λογικό ΚΑΙ, χωρίς «ή» και χωρίς συνθήκες χρόνου. Αν χρειαστεί, προσθέτουμε `anyOf` με νέο ADR.
- Οι αλλαγές σε αποστολή χρειάζονται νέο release. Το `version` επιτρέπει στα ενεργά playthroughs να ξέρουν με ποια έκδοση ξεκίνησαν.

## Εναλλακτικές που εξετάστηκαν

| Εναλλακτική | Γιατί απορρίφθηκε |
|-------------|-------------------|
| Μία Java κλάση ανά αποστολή | Παραβιάζει το MVP-9: κάθε νέα αποστολή θέλει κώδικα. |
| Αποστολές στη βάση, με οθόνες διαχείρισης | Ουσιαστικά Mission Builder, που είναι προαιρετική επέκταση. Περισσότερη δουλειά, χωρίς όφελος για το MVP. |
| Μηχανή κανόνων (π.χ. Drools) ή γλώσσα εκφράσεων | Η εκφώνηση λέει ρητά ότι δεν ζητείται. Δυσκολεύει τους ελέγχους και το PIT. |
| JSON αντί για YAML | Ισοδύναμο τεχνικά, αλλά λιγότερο αναγνώσιμο για τη συγγραφή περιεχομένου και χωρίς σχόλια. |
